# OpenSpec bundle — snapshot of `openspec init` output

This folder ships a per-tool snapshot of the artifacts that the official OpenSpec CLI (`@fission-ai/openspec`) generates on `openspec init`: slash commands / workflows and SKILL packages for `/opsx:propose`, `/opsx:apply`, `/opsx:archive`, `/opsx:explore`, `/opsx:sync`, `/opsx:update`.

- One subfolder per supported tool (`cursor/`, `claude-code/`, `codex/`, `opencode/`, `kilocode/`); each mirrors the exact relative paths the CLI writes into a project (e.g. `cursor/.cursor/commands/opsx-apply.md`). The installer copies a tool's subtree during `init` / `add` / `update` — see `AGENT-INSTALL.md → Place / Shared OpenSpec scaffold`. Note: the Kilo Code subtree is stored in the upstream `.kilocode/` layout (`workflows/` + `skills/`), but the installer remaps it to `.kilo/` on placement (`workflows/` → `.kilo/commands/`, `skills/` → `.kilo/skills/`) so Kilo Code gets a single project folder that matches `adapters/kilocode.yaml`; an earlier `.kilocode/` install is cleaned up on `update`. Since OpenSpec 1.13 the Codex subtree comes in the vendor-neutral `.agents/skills/` layout and is remapped to `.codex/skills/`, and the OpenCode `.opencode/commands/` folder is remapped to `.opencode/command/` — both matching their adapters, so install destinations stay the same as with earlier bundles.
- `version.txt` — the OpenSpec CLI version the snapshot was generated from; recorded in `.ai-rules.json` under `integrations.openspec.artifactsBundleVersion` on install.
- Codex ships SKILLs only (no project slash commands); `kimi`, `qwen`, `command-code`, `cline`, `pi`, and `other` have no bundle — see `README.md → OpenSpec`.

To refresh the snapshot, run `tools/refresh-openspec-bundle.ps1` with the absolute Node executable and OpenSpec JS entrypoint, their SHA-256 hashes, and the exact `-ExpectedVersion` selected for the controlled fork. The script refuses a different executable or version; it never resolves a global `openspec` command. Review the generated diff and `version.txt` together with the workflow dependency pin. Do not hand-edit the generated files — they are overwritten on the next refresh.

# r34: advisory diagnostics for unassigned form command actions

This downstream correction retains the audited upstream commit
`410951e74fd3e6b7a763cf49757935b9a34d3f31` and the r33 content, reconstructed
through the workflow schema-3 overlay helper. It does not intake the later
upstream main tip observed as `bd868ebebf08757d83be9b91780128394e43da07`.

`form-validate` Check 8 now reports `COMMAND_ACTION_UNASSIGNED` as a warning
for absent, empty and whitespace-only Action values. Warnings do not consume
the error limit or cause a failing exit code. The managed-form router,
verification gate and error-fixer guidance require user notification, continued
work and no automatic dummy handlers, action bindings or command removal.

An unassigned command is distinct from an existing procedure with an empty
body. Malformed XML, duplicate command IDs, malformed event bindings and invalid
extension callType retain their structural errors. The platform contract is
documented in the Developer Guide, section 7.5.1; see the form-manage reference.

Acceptance covers the command-action variants, unchanged source hashes, mixed
advisory/error results, error-limit behavior, the host helper's visible warnings
and five actual branch11 forms. Fork Full qualification and normal workflow
delivery/install evidence remain required; local validator evidence alone does
not establish a delivered project update.
